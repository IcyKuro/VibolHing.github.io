★ Compétence 01 - Réaliser

Réaliser c'est aller du besoin client jusqu'à une application fonctionnelle, testée, documentée et déployée. En BUT 2, cette compétence monte d'un cran : on ne part plus d'une spécification claire, mais d'exigences floues qu'il faut clarifier, formaliser et traduire en code de qualité.

C'est une compétence qui a été très solicitée au cours des nombreux projets de la formation, notamment pour la SAE TableauLEGO.

AC21.01

Élaborer et implémenter les spécifications fonctionnelles et non fonctionnelles à partir des exigences

✓ Acquis

Pourquoi c'est acquis

Dans le cadre de la SAÉ 3.Real.01, l'architecture multi-composants (PHP → Java → C) rendait la phase de spécification essentielle. Sans des règles d'échange clairement définies entre les différents composants et cela en amont, le moindre écart sur les formats de données pouvait entraîner des bugs silencieux, particulièrement difficiles à identifier. J'ai donc pris l'habitude de formaliser à la fois les exigences fonctionnelles et les contraintes techniques avant de commencer le développement.

Preuves concrètes

  • SAE TableauLEGO : Spécification du pipeline image: flux PHP → JAR Java → binaire C, formats d'échange définis (chemin de fichier, paramètres de résolution, formats des pavages de retour)
  • R3.04 Qualité de développement : Projet Monetix, nécessité le suivi d'un Product Backlog bien précis pour répondre aux besoins clients
  • Contraintes non fonctionnelles gérées : limite de taille d'image acceptée, formats supportés (img2brick notamment)
AC21.02

Appliquer des principes d'accessibilité et d'ergonomie

⟳ En cours

Où j'en suis

Sur la SAÉ 3, le parcours utilisateur était long et exigeant: upload d'image, choix de résolution, attente du calcul, comparaison des pavages, commande... ce qui m'a poussé à travailler sérieusement l'ergonomie à chaque étape. L'accessibilité normée reste un axe de progression : je l'ai abordée en théorie mais pas encore appliquée de bout en bout sur un projet.

Preuves & limites

  • Maquettes Figma du parcours upload → sélection résolution → comparaison des 4 pavages → panier
  • SAE TableauLEGO : Indicateurs de progression pendant le traitement du pipeline (spinner, message d'état)
  • Limite : WCAG (Web content accessibility guidelines) non abordé dans un projet concret.
AC21.03

Adopter de bonnes pratiques de conception et de programmation

✓ Acquis

Pourquoi c'est acquis

Dans le cadre de la reprise du code du S3 pour la poursuite du projet, j'ai compris que les bonnes pratiques ne sont pas une option quand on travaille en équipe sur la durée. Commenter le code existant avant d'y toucher et organiser le dépôt GitHub avec des branches dédiées à chaque axe du projet ont été les deux leviers qui nous ont permis de collaborer efficacement sans tout bloquer.

Preuves concrètes

  • Commenter du code critique de manière claire et compréhensible pour autrui dans le cadre d'un projet en équipe (tel que la SAE TableauLEGO)
  • Gestion cohérente et adéquate d'un outil de collaboration tel que Github
  • R4.02 Qualité de développement : Tester chaque fonctionnalité (+ rédaction d'un cahier des tests complet)
AC21.04

Vérifier et valider la qualité de l'application par les tests

⟳ En cours

Où j'en suis

Sur le projet Monetix, un portail web de gestion de paiements par carte bancaire, les tests n'étaient pas négociables : nous ne pouvions pas nous permettre de faire des approximations quand on manipule des transactions financières et des données de compte. Cela m'a appris à tester méthodiquement la cohérence des données et les flux entre les différents rôles utilisateurs. Sur Bricksy, j'ai appliqué le même réflexe après chaque correctif pour éviter de casser l'existant. L'automatisation de ces tests reste mon principal axe de progression.

Preuves concrètes

    • Monetix : jeux d'essais sur les transactions, cas limites (données de carte invalides, répercussions des remises sur le solde actuel)
    • Monetix : vérification des actions possibles par l'administrateur (ajout/suppresion de compte, gestion des infos de compte..)
    • R4.02 Qualité de développement : rédaction des cas de tests et tableau d'itération
Projet phare

S3-S4 (En cours)

SAÉ TableauLEGO

Site de génération automatiquement de tableaux LEGO personnalisés à partir d'une image fournie par l'utilisateur. Après l'import de l'image et le choix des dimensions, le site propose après tout un processus inter-langages des pavages LEGO différents qu'il pourra alors commander. Dans la continuité, le projet évolue vers une startup intégrant un système de coupons obtenus via des mini-jeux, également accessibles depuis une application mobile connectée à la plateforme e-commerce.

PHP Java C Traitement image Ergonomie React Git
  • Implémentation rigoureuse et propre (code commenté, et partagé sur github) - AC21.03
  • Interface ergonomique et propice à un site de e-commerce - AC21.02
  • Tests de commandes, création de compte... - AC21.04
